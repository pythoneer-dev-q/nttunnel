# NTTunnel Bot

Telegram-бот выдачи подписок для WDTT (VPN через медиарелеи ВК): генерация ключей
`wdtt://`, обязательные каналы, админ-панель внутри бота, MongoDB.

## Возможности

**Пользователь**
- Листательный flow: все экраны редактируются по кнопкам (`edit_text`), VK-хеши — вводом текста (FSM).
- Регистрация по ТЗ:
  `Шаг 1 из 3 — приложение` (выбор WDTT / qWDTT) → 📖 **Соглашение** (технология AS IS, текст в админке)
  → `Шаг 2 из 3 — VK-хеши` (до 4 VK-хешей, из ссылки `vk.com/call/join/...`)
  → `Шаг 3 из 3 — готово` (пароль, лимит, список хешей, «Показать ссылку»).
- Подписка **бессрочная** (`expires_at=0`), лимит из настроек + авто-сброс счётчика трафика раз в N дней.
- «Мой конфиг | Трафик» — конфигурация с живым трафиком из панели.
- Реферальная программа: ссылка `t.me/<bot>?start=ref_<id>`, +5 ГБ пригласившему.
- Обязательная подписка на каналы с экраном «🔄 Я подписался — проверить».
- Рекламные кнопки в меню.

**Админка `/godmode`**
- 📊 Статистика: пользователи бота + статус панели WDTT.
- 👥 Пользователи: пагинированный список (на стороне MongoDB), полный профиль
  (в т.ч. подключение WDTT: пароль, ключ `wdtt://`, трафик, устройства, онлайн),
  действия: блокировка/разблокировка (вкл/выкл и в панели), лимит GB, лимит устройств,
  сброс трафика, удаление подписки, личное сообщение.
- 📤 Рассылка любого контента всем неблокированным с прогрессом (потоковая, без загрузки всех ID в память).
- 📺 Каналы обязательной подписки: добавление (@username / t.me ссылка / -100 ID), удаление.
- 🎯 Рекламные кнопки: CRUD.
- ⚙️ Настройки: регистрация вкл/выкл («нет мест»), слоты, лимит GB/устройств по умолчанию,
  период авто-сброса трафика, текст соглашения, ссылки приложений.
- 🔌 Сервер: inbound панели (порты, DNS, активные/онлайн), рестарт WDTT/Xray.

## Архитектура и кэширование

Панель WDTT **не имеет** эндпоинта «получить пользователя по паролю» — единственный
способ найти пользователя — прочитать весь список (`GET /panel/api/users`). Чтобы
не дёргать панель на каждое действие в боте, данные пользователей кэшируются
в трёх слоях.

**Порядок чтения** (`WdttClient.find_user`):
1. **in-memory индекс** — строится из последнего снапшота панели, поиск O(1)
   по паролю/`password_key`/комментарию;
2. **зеркало в MongoDB** (`panel_users`) — переживает рестарт бота и работает,
   когда панель недоступна;
3. **панель** — только при `force=True` (создание конфига, действия админа) или
   на холодном старте, когда предыдущих слоёв ещё нет.

**Фоновая синхронизация** (`panel_sync_loop`, интервал `PANEL_SYNC_SEC`, по умолчанию 45 сек):
один `GET /panel/api/users` → обновляет и in-memory индекс, и зеркало `panel_users`,
и `panel_state` (inbound/main_password). Удалённые в панели вручную пользователи
вычищаются из зеркала.

Итог: на «обычные» чтения (кнопки «Трафик»/«Подписка») панель **не опрашивается** —
читаем локально; панель дёргается по расписанию и при изменяющих операциях.

Кэши-помощники (in-memory): каналы/реклама — 30 сек, membership — 90 сек,
разделы меню — 30 сек (с инвалидацией при изменении), настройки — 20 сек
(с инвалидацией при `save_settings`).

## Запуск

```bash
pip install -r requirements.txt
copy .env.example .env   # укажите BOT_TOKEN и ADMINS
python bot/main.py       # или: python run.py / python -m bot / python -m bot.main
```

- **Основной источник кредов — `.env`** (см. `.env.example`). Файл `creds.txt`
  (`BASE-URL`, `ADMIN-USERNAME`, `ADMIN-PASSWORD`, `VPN-PASSWORD`,
  `USER-DEFAULT-LIMIT`, опционально `BOT-TOKEN`/`ADMINS`) остаётся запасным
  вариантом и **не коммитится** в git.
- База API панели — `/wdtt`, см. `api_spec.md`.
- MongoDB: локальная или `MONGO_URI`.
- Бот должен быть **администратором** всех обязательных каналов (право чтения участников).

## Конфигурация (`.env`)

| Переменная | Назначение | По умолчанию |
|-----------|------------|--------------|
| `BOT_TOKEN` | токен от @BotFather | — |
| `ADMINS` | ID админов через запятую | — |
| `MONGO_URI` / `MONGO_DB` | подключение к MongoDB | `mongodb://localhost:27017` / `nttunnel` |
| `PANEL_BASE` | URL панели (без `/wdtt`, добавится сам) | `https://127.0.0.1:2860/` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | логин/пароль админа панели | `admin` / — |
| `VPN_PASSWORD` | главный пароль VPN | — |
| `SUB_URL` / `SUB_PATH` | база подписок | — |
| `SSL_INSECURE` | `1` = игнорировать self-signed сертификат | `1` |
| `USER_DEFAULT_LIMIT` | лимит трафика по умолчанию | `175 GB` |
| `PANEL_SYNC_SEC` | интервал зеркалирования пользователей (сек, мин. 10) | `45` |

## Покраска кнопок

Инлайн-кнопки Telegram нельзя красить нативно, поэтому есть хелпер:

```python
from bot.keyboards import btn
btn("Я скачал", cb="u:agree", style="success")   # 🟢
btn("Да, создать подписку", cb="u:create", style="danger")  # 🔴
```

`style='success' | 'danger' | 'warn'`. Зелёная/красная кнопки флоу регистрации уже покрашены.

При каждом апдейте синхронизируется: username, имя, язык, Telegram Premium, дата регистрации,

## Подготовка к публикации в git

- В репозиторий **не должны попадать**: `.env`, `creds.txt` (реальные токен бота и
  пароль панели), логи, `__pycache__`, venv, локальные данные — всё это уже в `.gitignore`.
- Перед первым коммитом проверьте, что секреты не попали в историю:
  `git status --ignored`. Если `creds.txt`/`.env` уже были закоммичены ранее —
  смените токен бота и пароль панели и почистите историю (`git filter-repo`).
- Для нового репозитория:

  ```bash
  git init
  git add .
  git status            # убедитесь, что .env и creds.txt НЕ в списке
  git commit -m "NTTunnel bot"
  ```

## Коллекции MongoDB

| Коллекция | Назначение |
|-----------|------------|
| `users` | профили пользователей бота, подписки, счётчики |
| `panel_users` | зеркало пользователей панели WDTT (фоновая синхронизация) |
| `panel_state` | последний `inbound`/`main_password` панели |
| `channels` | обязательные каналы для подписки |
| `ads` | рекламные кнопки |
| `settings` | глобальные настройки |
| `events` | журнал событий (аудит) |
| `tickets` | обращения в поддержку |
| `sections` | динамические разделы меню |

## Ограничения / заметки

- Токен бота и пароли панели не хранятся в репозитории — только в `.env`/`creds.txt` (gitignored).
- Если бот потеряет админку в канале, проверка участников падает — такие попытки считаются
  пройденными (пользователи не блокируются), а администратор увидит предупреждение в логах.
- Читаемые кнопки отдают данные из локального кэша/зеркала: «живость» обеспечивает
  `PANEL_SYNC_SEC`. Уменьшайте интервал, если нужна более свежая статистика (ценой
  более частых запросов к панели).
- Авторизация в панели WDTT реализована с автоопределением **CSRF-токена** (некоторые сборки
  требуют `_csrf`/`X-CSRF-Token` при логине — отсюда исчезает ошибка «invalid csrf token»).
  Если твоя версия панели не использует CSRF, клиент просто не найдёт токен и войдёт как раньше.
