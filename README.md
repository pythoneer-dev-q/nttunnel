# NTTunnel Bot

Telegram-бот выдачи доступов к VPN-панели **WDTT** через её REST API v2
(Remnawave-style). Бот не хранит ключи у себя: панель создаёт пользователя и
отдаёт готовые ссылки `wdtt://` и ссылку подписки — бот показывает их, считает
трафик и управляет лимитами.

## Что умеет

**Пользователь**
- `/start` → меню с трафиком: использовано / лимит, полоса заполнения, срок,
  устройства, статус.
- **🔑 Создать доступ** — соглашение → панель создаёт пользователя → сразу
  экран «Мой доступ» с паролем, трафиком и ссылками.
- **📱 Мой доступ** — первые `NODES_COPY_LIMIT` нод (по умолчанию 5) кнопками
  `CopyTextButton` (тап = копирование ссылки), остальные — в подписке
  («📦 Подписка · ещё N»).
- **📦 Подписка** — `sub_id`, ссылка подписки, трафик, число нод; в подписке
  доступны все ноды кластера.
- **🚀 Рефералка** — `t.me/<bot>?start=ref_<id>`, бонус ГБ пригласившему
  (начисляется в панели, если у него не безлимит).
- **🆘 Поддержка** — тикеты, переписка с админом.
- Обязательная подписка на каналы, рекламные кнопки, динамические разделы
  меню, инструкция со ссылками на приложения.
- Трафик показывается **всегда**, в том числе когда он равен нулю или лимит
  безлимитный.

**Админка `/godmode`**
- 📊 Статистика: бот + панель (версия, аптайм, RAM, службы, трафик), ноды
  онлайн/всего, число пользователей в панели.
- 👥 Пользователи панели: список с пагинацией, поиск по `name`/`comment`/
  `password`/`tg_id`, профиль (пароль, трафик, срок, устройства, ноды,
  Telegram ID), действия: лимит ГБ, устройства, срок, сброс трафика,
  блокировка/разблокировка, удаление, личное сообщение.
- 🌍 Ноды: список с пейджингом, карточка, `ping` (проверка адреса), добавление
  и удаление.
- 📤 Рассылка, 📺 Каналы, 🎯 Реклама, 🧩 Разделы, 🎫 Тикеты.
- ⚙️ Настройки: регистрация, места, лимиты по умолчанию, авто-сброс трафика,
  реферальный бонус, число нод кнопками, соглашение, ссылки приложений.

## Требования

- Python 3.10+
- MongoDB (локальная или удалённая)
- Панель WDTT с включённым REST API v2 на порту `:2860`

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env      # Windows: copy .env.example .env
# заполни BOT_TOKEN, ADMINS, PANEL_BASE и PANEL_API_KEY
python run.py             # или: python bot/main.py
```

Развёртывание как systemd-сервис — см. `deploy/README.md`.

## Конфигурация (`.env`)

| Переменная | Назначение | По умолчанию |
|-----------|------------|--------------|
| `BOT_TOKEN` | токен от @BotFather | — |
| `ADMINS` | ID админов через запятую | — |
| `MONGO_URI` | строка подключения MongoDB | `mongodb://localhost:27017` |
| `MONGO_DB` | имя базы | `nttunnel` |
| `PANEL_BASE` | базовый URL панели, клиент сам добавляет `/api` | `https://127.0.0.1:2860` |
| `PANEL_API_KEY` | ключ `X-API-Key` (рекомендуется) | — |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | fallback-логин для JWT | `admin` / — |
| `PANEL_TIMEOUT` | таймаут запросов к панели, сек | `30` |
| `SSL_INSECURE` | `1` = не проверять self-signed сертификат | `1` |
| `VPN_PASSWORD` | главный пароль VPN (для добавления нод) | — |
| `SUB_URL` / `SUB_PATH` | публичная база подписок (необязательно) | — |
| `ADMIN_PATH` | путь админки в веб-панели (справочно) | `/godmode/` |
| `DEFAULT_TOTAL_GB` | лимит трафика новым доступам, ГБ (0 = безлимит) | `175` |
| `DEFAULT_MAX_DEVICES` | устройств на доступ | `2` |
| `DEFAULT_EXPIRES_DAYS` | срок доступа, дней (0 = бессрочно) | `0` |
| `NODES_COPY_LIMIT` | сколько нод показывать кнопками копирования | `5` |
| `REFERRAL_BONUS_GB` | бонус пригласившему, ГБ (0 = выкл.) | `5` |

`PANEL_BASE` указывается **без** `/api`. Если панель смонтирована под
префиксом, укажи его в базе: `https://host:2860/wdtt` → клиент обратится к
`/wdtt/api/users`.

Приоритет источников: переменные окружения → `.env` → `creds.txt`
(legacy-файл, не коммитится).

## Как это работает

1. `bot/wdtt.py` — тонкий асинхронный клиент REST API v2: `X-API-Key` либо
   JWT (`POST /api/auth/token`) с авто-перевыпуском по 401. Ответы панели
   разворачиваются из `{"success": true, "data": …}`.
2. `bot/services.py` — чтение доступа, снимок трафика в MongoDB
   (`panel_*` поля) с TTL 60 секунд, список ссылок нод.
3. `bot/keyboards.py` — все инлайн-клавиатуры, включая логику
   `CopyTextButton` и «остаток нод в подписке».
4. `bot/texts.py` — лаконичные HTML-экраны, полоса трафика, статусы.
5. `bot/handlers/*` — пользовательские сценарии; `bot/handlers/admin/*` —
   админка.
6. `bot/middlewares/check_sub.py` — профиль пользователя, блокировки,
   обязательные каналы.
7. `bot/scheduler.py` — авто-сброс трафика раз в `reset_period_days`.

Панель опрашивается только по действию пользователя/админа: кэш снимка живёт
60 секунд, кэш пользователя в клиенте — 5 секунд, кэш нод — 30 секунд.

### Ссылки на ноды

`GET /api/users/{id}` отдаёт конфигурации для всех активных нод, но поле с
ними зависит от сборки панели. Клиент собирает ссылки из `nodes`,
`connections`, `node_links`, `configs`, `links`, из вложенных `link`/`url` и
из мастер-ссылки `link`, подставляя имена нод из `GET /api/nodes`. Дубликаты
убираются.

Первые `NODES_COPY_LIMIT` ссылок показываются кнопками копирования (если
ссылка длиннее 256 байт — открывается экраном с `<code>`), остальные живут в
подписке.

## Коллекции MongoDB

## Безопасность

- `.env` и `creds.txt` в `.gitignore` — реальные токены и пароли в репозиторий
  не попадают.
- Перед публикацией проверь `git status --ignored`. Если секреты уже были в
  истории — смени токен бота и ключи панели, затем почисти историю
  (`git filter-repo`).

## Ограничения

- Если бот потерял админку в канале, проверка подписки считается пройденной
  (пользователи не блокируются) — в логах остаётся предупреждение.
- Самостоятельное удаление доступа стирает пользователя и в панели
  (`DELETE /api/users/{id}`), поэтому ссылка перестаёт работать сразу.
- При недоступной панели показывается экран «Панель недоступна» с кнопкой
  «🔄 Повторить»; при удалённом в панели пользователе — «Пересоздать доступ».
